# arch-review

새로 반영된 커밋을 별도 리뷰어 에이전트에게 검사시키고, 그 결과를 정리해 전달하는 오케스트레이션 스킬.
검사 주체는 새 pane의 리뷰어이고, 이 스킬을 실행하는 에이전트는 **결과 전달자**다. 직접 diff를 읽고 평가하지 않는다 — 사용자는 검사와 보고를 분리해 두길 원한다.

## 실행

```bash
bash "$(git rev-parse --show-toplevel)/.claude/skills/arch-review/scripts/arch-review.sh" [<git-range>]
```

Bash timeout은 600000(10분)으로 준다. 리뷰어가 검사하는 동안 스크립트가 블록되기 때문이다.

- 인자 없음: 마지막 검사 이후 로컬 브랜치 head 변화(새 브랜치·새 커밋·삭제)를 자동 감지해 그 범위만 검사한다.
- `<git-range>` (예: `main..HEAD`, `abc123..def456`): 감지 결과와 무관하게 그 범위를 즉시 검사한다. "변경 없음"인데 다시 보고 싶을 때 쓴다. 이 경우 감지 상태는 갱신하지 않는다.

상태·요청·결과 파일은 리포의 `.git/arch-review/` 아래에 쌓인다 (커밋되지 않음).

## 스크립트가 하는 일

1. 로컬 브랜치 head 스냅샷을 `.git/arch-review/state.txt`와 비교
2. 검사할 커밋 범위가 있으면 `request-<ts>.md`에 검사 지침을 쓰고, 현재 pane 오른쪽에 새 pane을 열어 `cc`로 리뷰어를 띄움
3. 리뷰어에게 요청 파일을 읽고 `result-<ts>.md`를 쓰라고 프롬프트 (`--wait`)
4. 결과 파일이 생기면 pane을 닫고 상태를 갱신

전제: zsh alias `cc` = `claude --dangerously-skip-permissions ...`, 준비 완료는 화면의 "bypass permissions on" 문자열로 감지.

## 출력 해석 (마지막 줄)

| 출력 | 의미 | 보고 |
|---|---|---|
| `BASELINE` | 첫 실행. 현재 브랜치 상태를 기준점으로 저장 | "기준점 설정, 다음 커밋부터 검사" 한두 줄 + 브랜치 목록 |
| `NO_CHANGE` | 새 브랜치/커밋 없음 | "변경 없음" 한 줄 |
| `META_ONLY` | 브랜치 생성/삭제만 있고 검사할 커밋 없음 | 그 내용 한두 줄 |
| `RESULT=<path>` | 리뷰 완료 | 아래 "결과 보고" 절 |
| `ERROR: ...` | 실패. 리뷰어 pane은 조사용으로 열어둠 | 원인과 pane ID를 그대로 전달 |

## 결과 보고

`RESULT=<path>`이면 `cat <path>`로 읽고, 같은 디렉토리의 `request-<같은 ts>.md`에서 "변경 감지 내역"(브랜치·범위·커밋 제목)을 가져와 먼저 보여준다. 그 다음 리뷰어의 결과를 **한국어로, 구조를 유지해** 전달한다:

- 요약
- 발견 사항: 번호 · `[심각도]` 제목 · 위치(`파일:라인`) · 문제 · 제안 — 리뷰어가 쓴 근거를 잘라내지 말 것. 사용자는 "왜 문제인지"를 보고 직접 판단한다.
- 잘한 점

리뷰어의 판단에 동의하지 않더라도 결과를 바꾸지 말고, 필요하면 마지막에 한 줄로 의견을 덧붙인다. 원본 파일 경로를 끝에 알려준다.
